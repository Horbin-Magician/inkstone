## 同步扫描：文件数量与大附件成本（2026-10-06）

Apple M4 / macOS 27.0.1 / Rust 1.97.0 release，真实同步扫描入口，完成 Scanning 后主动取消。由独立 Python 夹具生成器创建文件，六次测量进程分别使用新的恢复目录；所有远端方法设为不可到达断言。计时从扫描开始回调到读取清单前回调，不包含网络和后续验证复扫。

| 场景 | 扫描总计，三轮 | 枚举中位数 | 文件处理中位数 | 清单校验中位数 | 峰值 RSS 中位数 |
| --- | --- | ---: | ---: | ---: | ---: |
| 10,000 × 1 KiB（9.766 MiB） | 222.130 / 222.920 / 191.151 ms | 24.008 ms | 186.385 ms | 3.507 ms | 11.188 MiB |
| 9 × 64 MiB（576 MiB） | 1064.244 / 1070.431 / 1073.106 ms | 0.069 ms | 1070.360 ms | 0.007 ms | 5.656 MiB |

各列分别取中位数，不能将分项中位数相加当作总计中位数。文件处理包含路径校验、打开/读取、SHA-256 与清单插入及进度回调，并未单独隔离纯 SHA-256 CPU。小文件场景的数量开销可见，但本机大附件样本由文件处理主导；重复运行仍读取全部 576 MiB。后续优化优先评估文件处理，而非先优化清单校验；mtime/大小相同不构成内容不变的证明，本轮没有引入跳过内容读取的缓存。

这是本地生成后、未清理系统缓存的连续扫描，不是冷磁盘或端到端 WebDAV 吞吐，也不能替代真实服务商大库验收。原始记录 `target/sync-scan-yp26kbcm/manifest.json`、`results.json` 及每轮 stdout/time 文件，构建与执行日志为 `target/sync-scan-benchmark-build.log`、`target/sync-scan-benchmark-run.log`。六轮均在远端请求前取消，文件数/读取字节数与夹具一致，计量结束后逐文件 SHA-256 复核通过。
