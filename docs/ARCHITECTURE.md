# 架构与关键决策

## 依赖与许可

2026-09-28 核对 crates.io 发布索引、实际下载的 Cargo.toml 与源码：

- GPUI Component / Base / Kit `=0.7.0`，共同使用 `gpui-pre =0.3.7`。
- `Cargo.lock` 提交版本控制；`cargo tree -i gpui-pre --locked` 确认只有一个 GPUI 版本，测试支持也复用它。
- 上述主要 UI crate 采用 Apache-2.0；没有引入或复制 Zed GPL editor crate。
- 笔记功能通过公开接口扩展。实测发现 Unicode 边界问题后，对 gpui-base 0.7.0 维护六个文件的受控补丁，详见 [补丁说明](EDITOR_PATCH.md)；所有调用仍共用同一 Base 和 GPUI 类型。

参考：[官方仓库](https://github.com/longbridge/gpui-kit)、[发布索引](https://index.crates.io/gp/ui/gpui-component)、[编辑接口](https://docs.rs/gpui-component/0.7.0/gpui_component/input/index.html)。下载的组件对应上游提交 `0c830f4d257e69fdd17200650533ab4ca9a40cc0`。

## Cargo workspace

根 `Cargo.toml` 是虚拟 workspace，包含 `crates/inkstone-core` 与 `crates/inkstone-desktop` 两个默认成员，使用 resolver 3。共享依赖版本、release profile 与 `[patch.crates-io]` 只在根配置；`vendor/gpui-base`、`vendor/gpui-component` 显式排除出 workspace 成员，继续作为补丁依赖维护。

`inkstone-core` 提供 `inkstone_core` 库，拥有原 `lib.rs` 的全部核心模块；运行、构建和测试依赖均不包含 GPUI。`notify` 在 core 中只用于文件监听测试，平台安全文件操作的 `libc` / `windows-sys` 由 core 持有。Markdown 测试夹具与后台 benchmark 随核心代码放置。

`inkstone-desktop` 单向依赖 core，拥有原 `main.rs` 的桌面模块，二进制目标仍为 `inkstone`。GPUI、原生菜单和应用图标依赖只由 desktop 声明；字素补丁与展示对象集成测试也归入 desktop。macOS build script 在 desktop 内定位根目录 `packaging/macos/Info.plist`，打包脚本 `packaging/macos/bundle.sh` 输出根 `target/` 下的应用；正式图标放在 `crates/inkstone-desktop/assets/`，候选设计归入 `docs/design/branding/`。

核心层不得引用 desktop 或 GPUI 类型。共享类型和不依赖 UI 的算法放入 core，涉及 `Entity`、`Window`、焦点和原生图像的适配留在 desktop。包不独立发布，资源和受控依赖按整个仓库构建。

### 模块边界约定

桌面层使用 `Workspace` 和 `EditorPane` 作为 GPUI 实体及共享状态拥有者，子模块按职责实现其方法。子模块不复制文档状态，也不建立第二套保存、撤销或后台任务机制；跨子模块调用使用 `pub(super)`，不扩大应用外部接口。涉及多个功能的回归测试分别放在 `workspace/tests.rs`、`editor/tests.rs`，保留原来的测试名称和筛选路径；既有功能模块的局部测试继续就地维护。

核心层 `index` 不依赖桌面工作区。解析、搜索和链接模块通过 `Index` 快照与解析结果协作；`inkstone_core::index::parse`、`inkstone_core::index::ParsedNote` 等入口由父模块重新导出，调用方无需知道实现文件位置。索引回归放在 `index/tests.rs`。

新增功能优先放入对应职责模块：保存及恢复日志改动进入 `saving`，外部磁盘变化进入 `file_sync`，实时样式进入 `presentation`，索引搜索算法进入 `index/search`。顶层文件负责状态与组装，避免重新堆积功能实现。底层 Vault 的平台原子写入实现和 vendor 编辑器补丁沿用原有边界。

Markdown 文件是已保存正文事实来源。运行时索引驻留内存；应用数据目录中的启动缓存可丢弃，可从文件完整重建。缓存通过正文 SHA-256 校验，不能只依据大小和修改时间复用。恢复记录是显式草稿副本，不混入正文。

### 工作区所有权与保存事务（逐步拆分）

| 拥有者 | 持有状态与职责 | 边界 |
| --- | --- | --- |
| Workspace | 当前 Vault、索引 Arc、打开视图、工作区代次 | 切库使旧异步结果失效；负责 UI 事件和完成结果应用 |
| UiState | 偏好、弹窗/选择/滚动、同步调度状态 | 目前仍混合部分业务状态，后续继续分离，不当作全部拆分完成 |
| DocumentState（多个 Tab 共享 Rc） | 唯一正文编辑器、SaveState、草稿状态 | 各视图共享保存与撤销身份；不能按标签页复制保存事务 |
| SaveState（DocumentState 内） | 保存基线、dirty/saving/conflict/error、恢复日志正文标记 | 无 GPUI 依赖；集中编辑、普通保存、冲突处理、外部重载、重试和另存副本转换 |
| DraftState | 防抖时钟、重试和已完成正文标记 | UI 层采集已提交文本，IME 预编辑不交给后台 |
| DraftIo（Arc） | 草稿会话 Mutex、失效序号 | 草稿写入与正式保存共用锁，阻止已排队草稿在保存后复活 |
| SaveJob（移动到后台） | Vault、路径、基线、提交文本、可选 DraftIo | 不持有 Entity/Window/Rc；创建时使旧草稿任务失效，run 串行保存/清理 |
| settings_save::State（Workspace 内） | 最近持久化快照、错误、活动任务序号 | 私有字段与只读查询；合并写入、显式重试、切库重置；旧完成结果不能释放新任务 |
| Run（Arc 共享） | 单次同步身份、取消令牌、合并进度槽 | 无 GPUI 依赖；后台发布进度，UI 消费；进度轮询与完成回调均核对身份 |
| Schedule<W>（cloud_sync 内） | 排队来源、后续请求、合并/重试等待、运行中标记及泛型计时器句柄 | 无 GPUI 依赖；转换规则独立测试，替换/取消/重置时释放等待句柄 |
| SaveOutcome | 正文保存结果、独立草稿清理错误 | 清理失败不能将正文保存成功误报为失败；UI 据结果更新状态并安排重试 |

`SaveJob` 是 desktop 应用生命周期的协调器，不是另一套文件存储实现；实际路径校验、冲突检测和安全替换仍由 core Vault 完成。调度时从文档获取不可变快照，后台不读取当前 UI。完成后 `saving.rs` 先校验工作区代次和文档身份，再更新保存基线；期间继续输入仍按当前正文与新基线比较 dirty。

已提取普通保存与草稿清理事务，并将保存状态归入 SaveState；普通保存、编辑、冲突处理、外部重载、重命名和批量编辑路径使用状态转换方法。全部保存状态字段均为私有，UI 通过只读查询和转换方法访问，恢复日志去重/失败标记也通过方法更新。仅测试构建提供明确的故障注入接口，不进入生产构建；不得将此阶段描述为完整保存状态机或完整服务拆分。

同步队列策略由 `cloud_sync/schedule.rs` 管理；窗口适配层将 `Pump::Wait` 转为 GPUI 计时器，把到期事件送回队列，再检查保存、IME 和文件操作保护。自动请求不能延迟已排队的手动请求，新修改不能缩短重试等待；取消排队保留 busy，只有后台任务完成才释放运行中保护。切换笔记库/加载账户时重置队列并释放旧计时器；后台结果仍须通过工作区 generation 检查。进度槽和取消令牌由单次 Run 共同持有，克隆句柄关联同一身份。UI 重置丢弃句柄不会取消应用级后台任务；旧完成回调释放自身写入计数后，必须同时匹配 generation 和 Run 身份才能更新 UI。应用级 background_sync 保持网络任务运行至结束，最后一个窗口关闭后等待所有任务完成再退出。文件写入计数及设置输入当前仍由 cloud_sync/UiState 适配层协调，后续继续拆分。

工作区设置持久化位于 `workspace/settings_save.rs`，不再由大型 UI 模块保存后台事务状态。UI 仍拥有可编辑偏好与布局，协调器在保存前快照化，后台使用独立 Preferences 副本。成功后再次采集最新设置以合并期间修改；失败等待显式重试。完成回调同时检查工作区代次和任务序号；切库失败时可释放旧任务自身，不能清除其他任务标记。

设置视图由 `workspace/settings_ui.rs` 组装：统一分类导航、设置搜索、编辑器设置以及公共行/分组/滚动容器；各分类专用内容仍由 appearance、file_settings、hotkeys、backups、cloud_sync 负责。主 UI 只调用 settings_panel，避免设置页组装再次堆积在 ui.rs；通用开关的调用也直接指向 settings_ui。

通用弹窗由 `workspace/modal_ui.rs` 组装，包括遮罩/尺寸、命令与快速打开选择器、属性类型和列表控件，以及各业务弹窗的路由。焦点和按键处理随容器移动；设置/历史/草稿/冲突/附件等业务动作仍调用各自模块。主 UI 仅负责是否展示弹窗，共享按钮、主题和搜索结果的接口限于 workspace 模块。

右侧大纲、反向链接、出链、标签与属性面板位于 `workspace/right_sidebar.rs`，包括右侧分类按钮、标签导航和大纲折叠；大纲的路径/标题快照键及折叠集合由该模块私有管理。主 UI 通过 right_panel 组装，索引与笔记操作仍调用既有服务。

左侧文件树、文件名/全文搜索结果、排序、当前文件定位和树形引导线位于 `workspace/left_sidebar.rs`。快速打开弹窗复用其搜索结果接口，搜索后台调度仍由搜索模块维护。主 UI 通过 left_panel 组装左右侧栏，不再实现文件树绘制及搜索结果分组。

工作区通知由 `workspace/notifications.rs` 持有私有文本，生产者仅可 publish/append，视图只读 text。搜索重试通过 clear_matching 清除自身旧错误，不直接修改全局展示缓冲，也不误清较新的保存/同步提示；消息内容及原有单条覆盖语义保持不变。业务模块仍负责根据结果选择文案，状态栏和欢迎页只负责展示。

### 重命名的历史归属

`vault/history/links.rs` 在恢复目录按笔记库保存归属映射，键为不带 json/saved 后缀的日志路径。新重命名将映射作为带版本及 SHA-256 校验和的 `.history-commit` 提交记录发布，并尽力更新 `.history-links` 镜像；读取先校验提交记录，再修复缺失或损坏的镜像。没有提交记录时兼容旧 `.history-links` 格式，下一次重命名自动迁移。重命名转移当时可见的完整日志集合，连续重命名继续转移同一集合；旧路径重新创建的笔记仅拥有后续记录。正文保留原路径，预览显示记录原路径，恢复副本使用当前笔记路径。提交记录属于持久化恢复数据，不能作为缓存删除；旧格式在迁移前也不能删除。

重命名使用笔记库文件锁串行更新映射，先持久化临时映射，再移动文件和发布映射；发布失败尝试不覆盖文件的回滚，回滚受外部文件阻挡时保留两侧文件并报告实际位置。无效映射阻止历史读取及后续移动。索引沿用恢复目录时间戳失效。应用内目录重命名复用同一锁与发布/回滚流程，单次扫描日志元数据，按记录当前归属和仍存在的实际笔记路径转移；嵌套路径及此前单篇重命名均保留历史，已删除笔记的历史保留原归属。成功发布者在重命名锁内核对镜像，并单独保存 `.history-proof` 校验凭据；提交记录损坏/缺失时，仅在镜像与该凭据一致时继续读取归属，下次成功重命名重新发布权威记录。读取回退不会改写权威文件，以免覆盖并发发布。移动前凭据标为 pending，成功回滚才恢复旧凭据；无凭据、过期镜像及无法确认结果的发布均不会被猜测为有效归属。镜像或凭据写入失败不影响有效权威记录。`links/intent.rs` 在移动前原子持久化带校验和的意图，保存移动前后映射、原凭据、暂存文件和对象身份（卷号、文件标识、可用时的创建时间）。历史读取或下次移动发现遗留意图时，在同一文件锁内协调：原对象仍在源路径则撤销意图；原对象已在目标路径则补发映射；已发布则补齐镜像/凭据并清理。协调只更新恢复元数据，不移动或覆盖笔记。两侧身份均不匹配或均匹配时保留意图并报告无法确认，外部同内容替换不会被当作移动成功。外部重命名、物理断电保障、多份记录同时损坏及身份不明时的人工处理入口仍待补齐。

### 回收站展示元数据

`vault/trash_metadata.rs` 的 `trash_inventory` 单独提供记录时间和大小，恢复授权继续使用不递归统计的 `trash_entries`。时间来自原路径描述文件；大小为普通文件逻辑字节数，迭代遍历目录并排除链接目标，统计错误或溢出返回未知。界面将基础列表/草稿读取与大小统计分为独立后台任务，均按笔记库代次及请求号筛掉过期结果；未取得元数据时显示未知，空目录明确为零。回收站注明不自动清理及拒绝覆盖原路径。

### WebDAV 流式接收边界

`Remote::download_to` 接收调用方提供的 Write 目标。WebDAV 使用固定 64 KiB 缓冲直接传输，先检查 Content-Length，再按实际字节限制对象大小；分块编码同样受限制，读取或目标写入失败立即返回。其他 Remote 实现可暂用兼容的 Vec 回退。云端已存在对象的上传冲突校验使用摘要写入器，不再保存整个下载正文。主同步流程通过 `downloads.rs` 在恢复目录按笔记库及远端身份隔离暂存目录，以固定缓冲写入临时文件并同步计算哈希；校验通过才发布为按摘要命名的对象。重试时重新流式校验已完成对象，避免重新下载；普通失败/取消清除当前部分文件，保留完整对象。所有对象准备完毕后仍按原顺序复核本地、上传、发布、应用和保存基线；成功后清除本次使用的暂存对象。应用前再次校验暂存正文。整批仅保存路径，移除了 512 MiB 上限；单文件仍限制 128 MiB，下载应用以固定 64 KiB 缓冲从暂存对象复制到目标同目录临时文件，并复核实际字节及摘要后才发布；写入或校验失败清除临时文件且不替换原件，沿用替换备份和并发修改保护。新增 `Remote::upload_file` 接收调用方持有的私有不可变文件快照；WebDAV 先以固定缓冲校验摘要、复位游标，再通过带长度的文件 Body 发送，保留条件创建和已有对象复核。其他 Remote 可使用 Vec 兼容回退。主上传流程尚未接入快照接口，仍使用逐文件 Vec；扫描、应用前基线比较及备份复核改为固定 64 KiB 缓冲计算摘要，按块检查取消（提交阶段保持原不可取消规则），并按实际读取字节维护进度/大小限制。取得笔记库同步锁后、启动工作线程前，仅清理当前远端暂存目录内符合数字进程号/时间/序号命名规则的普通 `.partial` 文件；目录、链接、未知文件及完整对象保留。强退后的完整对象复用及部分文件清理由真实子进程 kill 回归覆盖。失败遗留但后续不再需要的完整对象及目录容量治理待补齐；不支持 HTTP 字节范围续传。576 MiB release 回归已通过；流式扫描/比较及下载应用后进程峰值从约 1.14 GiB 降至约 8.47 MiB。独立上传快照接入后，576 MiB 上传测试峰值约 8.80 MiB。这些是生成远端的传输流程测试，真实 WebDAV 和更多规模仍待验证，不能据此宣布全部资源预算验收通过。

### 同步备份恢复清单

`vault/sync/recovery.rs` 提供元数据清单，扫描与同步一致的可见目录，识别 `.inkstone-sync-*.backup.json` 描述及其相邻备份。校验原路径、描述/正文文件名对应关系、相同父目录、普通文件类型和哈希格式，拒绝链接及越界；单条坏记录或不可读子目录计入异常数量，其他有效记录继续返回。清单只读取描述及文件元数据，返回原路径、备份路径、时间、字节数和同步前预期哈希，不读取正文、不宣称实际内容已通过哈希校验。并发外部修改可能使真实保留内容不同于同步基线，后续恢复必须保留这些内容。容量合计仅覆盖有效清单中的正文，不包括描述及孤立文件。`restore_copy` 在重新核对所选记录后以 64 KiB 缓冲复制到同目录隐藏暂存文件，计算实际 SHA-256，复核文件身份/大小/时间及描述，再以不覆盖的硬链接发布独立副本；避让磁盘文件和调用方提供的未保存路径，保留原件、备份及描述。同步前预期哈希不符时仍保留并返回恢复内容，但明确报告不一致，因为这可能是同步保护捕获的并发编辑。流式复制不超过选中记录的字节数，异常不发布副本。`workspace/sync_recovery.rs` 在统一文件恢复面板后台读取清单，按笔记库代次及请求号隔离过期结果；列表按可见行构建，显示来源、路径、时间、大小和保留策略。恢复任务纳入 pending_file_writes 并避让全部打开标签路径，完成后刷新文件索引、调度同步及报告基线差异。当前笔记历史、草稿比较与回收站沿用原恢复行为，从同一入口进入。草稿枚举返回记录时间和字节数，统一列表直接显示，不在绘制时读取文件元数据；历史面板按当前保留设置显示天数与容量，零值明确表示不限，并注明最新成功版本保护及草稿不自动清理。

### 历史元数据缓存（逐步迁移）

`vault/history/index.rs` 在恢复目录的 `.history-index` 中，以规范化笔记库根路径和笔记相对路径的 SHA-256 键保存独立元数据索引。缓存不含正文，带格式版本、范围、目录修改时间及内容校验和；命中时只校验本笔记的记录类型、大小和修改时间，历史正文仍由 read_history 在用户选择记录后读取并校验归属。目录新增/删除/扩展名变化或缓存损坏时重建；写缓存失败和缓存目录链接不会阻断历史列表。缓存通过临时文件替换，原始恢复记录始终保留。

`vault/history/records.rs` 在 `.history-index/records` 缓存每条日志的归属、大小和修改时间，并校验缓存版本及内容校验和。目录变化后的重建仍扫描目录，但未变化的日志复用元数据，仅新日志或失效记录读取正文；json→saved 发布复用同一元数据键。`Vault::journal` 完成日志持久化后直接使用内存中的记录生成归属缓存，不复制正文；新日志首次列出历史也无需读取正文。缓存不可用时回退读取原记录，初次导入旧历史仍需读取正文。扫描消除及过期元数据清理待后续完成。缓存依赖应用生成的不可变历史记录及文件元数据变化；手工修改正文同时伪造原大小/修改时间不属于缓存有效性保证，恢复选中记录仍重新读取原文。

### 索引的用途与维护成本

- 路径、文件名和别名查找表用于链接解析和同名歧义判断；最短链接生成复用文件名查找表，不另建全库计数表。反链表避免每次展示反链都扫描全部笔记。
- 索引快照共享正文、解析结果和查找表。正文相同时不重新解析；仅正文（链接目标和别名不变）或文件时间变化时保留名称表和反链；链接目标变化只调整该笔记的反链。新增、删除、重命名和别名变化会影响其他笔记的解析，仍需重建反链。
- 全文搜索保留原有子串、正则及结构化条件语义，没有新增倒排索引或持久化数据库。搜索先过滤未达上限时的不匹配笔记，已有足够匹配笔记后延迟其余匹配工作，按展示顺序取足结果即停止；少量结果和无结果查询避免排序全库。快速打开只对前 200 项排序并创建结果对象。
- 文件内容和时间从同一个已验证的文件句柄读取；写缓存借用解析结果并缓冲输出，不深复制全库解析结果，也不先生成完整 JSON 字节数组。
- 链接补全仅在笔记路径、别名、标题名称、块 ID、附件列表或链接偏好变化时失效；普通正文和位置变化复用已有补全列表。快照比较仍需遍历笔记引用，但避免逐个打开视图重建全库补全对象。

全文搜索无匹配时仍需扫描全部正文，结构变化仍可能重建全部反链，快照的笔记目录仍有 O(N) 复制成本。是否增加全文倒排索引，应以后续大库的查询耗时、内存和更新成本实测决定；当前先降低现有索引的重复维护开销。测量条件和结果见 [验证指南](TESTING.md)。

## 编辑器路线

比较三个方向：

1. 公开接口扩展：复用 IME、文本选择和历史；TextDecorationCollection 提供实时样式，DefinitionProvider / CompletionProvider 提供双链交互。
2. 受控组件分支：修复软换行和光标的字素边界，并提供保留选区的光标滚入视口接口。需要维护跨块 Unicode 回归与原生几何测试。
3. 独立编辑器：自由度最高，需要重新实现输入、撤销、选择和平台接口，首版成本与风险更高。

实时预览通过零宽标记隐藏非活动文字语法，标题按级别设置字号与行高；复杂内容使用独立 `DisplayObject` 投影，首行预留宽度和测量高度，其余源行只在展示层隐藏。图片、表格、Callout、嵌入、公式和图表复用阅读片段或后台图形资源；光标或选区进入时展开源码。正文、复制、选区和撤销继续使用原始 Markdown 坐标。

`syntax::Snapshot` 复用同一版本的语法树、注释遮罩和行内脚注范围；公式与代码不贡献伪双链、任务、标签或标题。普通金额重新按正文解析，保留其链接与脚注。阅读片段保留完整来源文件快照，交互执行前检查版本。

公式与 Mermaid 使用纯 Rust 适配器输出 SVG，GPUI 按 DPI 准备原生图像。打开笔记时只排版全部公式以预留尺寸，字形轮廓和栅格化仅针对当前视口及相邻一屏，后台每批最多 4 个；滚动到附近后再继续。服务在视图间共享最多 64 MiB 图像缓存和 4096 条排版结果。阅读通过 MarkdownPlugin 读取缓存，缺图时通知编辑器补栅格。字形轮廓嵌入，中文回退到系统字体。展示坐标与文件字节之间的映射不会写回笔记。

## 位置与异步边界

- Markdown / 编辑范围：UTF-8 字节半开区间，保留换行和原始格式。
- IME：EntityInputHandler 使用 UTF-16；直接集成测试覆盖 emoji 代理对与组词。
- 字素：unicode-segmentation 覆盖 ZWJ emoji、组合附加符号；实际光标几何仍由组件处理。
- 组件内部 LSP Position 的字符列通过 RopeExt 转换，不能直接当作 UTF-16 IME 范围。
- 可见位置、软换行、候选窗：组件 DisplayMap / 平台文本系统负责，多 DPI 仍待实测。
- Markdown 样式与 AST 在后台解析；安装结果时比较代次及当前原文。阅读组件也有后台解析和版本检查。
- 搜索绑定查询代次、笔记库代次。打开笔记绑定导航代次。外部重载比较路径、baseline 与保存状态。
- 普通文件事件只更新相关索引项；目录创建或导入时扫描目录并增量刷新，完整重扫请求重建索引。删除条目通过索引维护入口同步清理名称表和反链。索引复制与解析在后台。索引快照通过 `Arc<IndexedNote>` 共享未变化的正文及解析结果，修改正文或文件时间时只替换对应笔记，避免每次监听事件深复制全库内容。目录树用组件虚拟列表，目录列表改变时才重建树。
- 反链使用虚拟列表，最多占四行高度，全部结果仍可滚动访问；避免万条反链把编辑器挤出窗口。列表改变时重置滚动位置。
- 标签切换、关闭标签和源码 / 阅读切换显式把焦点交给当前视图；各标签编辑实体继续保留历史和选区。

## Windows 保存

1. 先把 baseline 与 draft 写入应用恢复区并 sync_all。
2. 检查磁盘版本；持有允许读和删除、禁止其他写访问的源文件句柄。已有外部写句柄会使保存失败，不继续替换。
3. 新字节写入同目录唯一临时文件并 sync_all。
4. 新建使用不覆盖 hard_link；已有文件用 ReplaceFileW，备份位于同一卷。
5. 比较备份文件身份与受保护句柄，同时比较 baseline。发生替换竞争，保留外部备份与草稿并报告冲突。
6. 成功后移除受保护的临时备份；恢复记录改为 `.saved`。失败记录保留 `.json`。

[Microsoft ReplaceFileW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew) 说明部分错误可能改变文件名称，且 WRITE_THROUGH 标志不受支持。实现保留备份和恢复日志，不宣称所有设备下绝对断电原子性。普通写错误会保留内存、显示标签错误并停止自动重试。冲突需要另存副本，不自动决定使用哪个版本。

删除使用同卷回收区；Windows 重命名用 MoveFileW，不覆盖已有目标。macOS 使用 `renameatx_np(RENAME_EXCL)`，Linux 使用 `renameat2(RENAME_NOREPLACE)`，文件和目录均拒绝覆盖已有目标。

macOS/Linux 保存先将草稿移到唯一备份名称，再通过 `RENAME_SWAP` / `RENAME_EXCHANGE` 原子交换目标与草稿；备份因此捕获实际被替换的文件，不存在先硬链接旧文件再覆盖新文件的窗口。交换后核对原文件身份和基线，冲突保留两者。Unix 保留原文件权限。文件系统不支持原子交换时明确报错，不退回不安全替换。Unix 外部程序持有旧文件句柄进行延迟原地写入仍不能由本应用禁止，备份保留用于恢复；Linux 与真实断电行为尚未在本轮验收。

## 当前 GPUI 判断

原生笔记闭环、阅读、搜索和基础输入有运行证据。长段落测试发现了组件原生的字素拆分问题，现已采用受控补丁，并承担后续升级回归成本。可以继续使用 GPUI 推进 MVP；多 DPI、完整原生光标回归和交互性能完成前，不能宣称生产级编辑体验。


## 阅读来源映射与双视图

`workspace/views.rs` 管理双视图，每份打开的文件只使用一个正文保存者与撤销栈；镜像视图保留自己的选区、滚动和阅读模式。输入法预编辑不复制到另一视图。

`rendering.rs` 将原始 Markdown 转为阅读展示，并保存原文件位置到展示文本的映射。嵌入展开后的链接携带来源路径，任务携带来源位置和文本快照。更新任务时检查快照，修改打开文档的正文或通过 Vault 安全保存关闭的来源文件；不会将展示用的链接协议或 HTML 写入笔记。闭合来源的写入计入退出等待，提交后立即更新匹配版本的索引。

TextView 的可选任务回调只报告位置与目标状态；源文本修改和冲突处理留在应用层。源偏移到阅读块位置的查询用于保持阅读模式的大纲/块跳转。


## WebDAV 同步边界

核心 `Remote` 接口隔离传输与合并，首个实现是 reqwest blocking + rustls WebDAV。桌面端只在后台执行客户端初始化与网络请求；服务器配置进入 Preferences。密码不进入配置、清单或基线：以明文保存在应用数据目录的 `webdav-secrets.json`，账号键是服务器、用户名与笔记库路径的 SHA-256。读取失败不会在随后的空密码保存中删除旧项。同步时复用文件操作互斥和未完成写入计数，阻止库切换与提前退出。已配置且开启自动同步时，打开笔记库以及本地新建、保存或删除后会排队同步；文件变化先等待短暂静默，失败后退避重试。未配置或关闭自动同步时仍只在手动点击后同步。

远端内容对象不可变，清单通过强 ETag 和条件 PUT 发布；先校验全部下载，再发布合并清单，最后应用本地文件并推进设备基线。失败保留旧基线，允许重试；提交后本地应用不是整库事务，部分成功需要下一次同步完成。本地按内容哈希重新检查变化，替换或删除保留隐藏备份，不执行无恢复的删除。设备基线和进程文件锁放在库外应用恢复目录，避免同步状态自身参与同步。校验值保护内容完整性，不提供端到端加密。

## 独立草稿生命周期

文档共享状态持有草稿会话，各视图合并后的已提交正文是写入源。工作区轮询只安排后台恢复写入：800 ms 防抖、连续编辑最长约 5 s 检查点；组词期间跳过，不调用 Markdown 保存。写入成功后退休本会话旧记录，错误保留上次成功记录并按 5 s 间隔重试。

每个文档的草稿与正式保存共用互斥锁；正式保存使已排队草稿版本失效，在后台保存成功后清理对应草稿，避免任务乱序重新生成已保存草稿。保存过程中继续输入会在保存完成后重新进入草稿调度。撤销到磁盘基线会安排清理；冲突和保存失败仍可独立写草稿。关闭沿用显式保存保护，异常退出保留最近发布的 JSON，旧会话记录不由新会话擅自删除。恢复为副本不覆盖原文件。

### 整库备份容量清单

`vault/backup/capacity.rs` 提供用户选定备份父目录的一层清单及单备份摘要。复用清单格式、路径、目录布局、普通文件类型和大小检查，仅读取清单正文与文件元数据，不读取备份正文或声称内容校验通过；恢复仍通过 `inspect` 逐文件核对 SHA-256。返回备份路径、创建时间、来源名称、文件数、正文逻辑字节数及清单字节数，累加使用溢出检查。统计不包含文件系统分配开销和额外根目录文件。损坏备份、不可读条目和拒绝的链接单独计数，不进入合计；忽略未知目录和隐藏的未完成备份暂存目录。`workspace/backup_capacity.rs` 在备份设置页后台读取清单，按笔记库代次、备份位置及请求号拒绝旧结果；选择目录或备份成功后刷新，也提供手动刷新。按可见行绘制来源、时间、文件数及容量，并提供显示目录操作，明确统计范围与未校验内容。当前无删除行为；清理预览及恢复保护规则待后续接入。


整库备份清单新增可选 `source_id`，以规范化来源路径、目录卷/文件身份及创建时间计算摘要，不写入原始路径或笔记内容；同名库及原路径重新创建的目录分开归类。缺少可用创建时间时不生成身份。目录移动、跨盘或身份变化可产生新的保留分组，采用保守保护，不承诺永久库身份。旧清单无该字段仍可完整校验和恢复，容量摘要返回未分类；后续清理预览必须保护未分类记录，不可仅按 `source_name` 推断可删除性。

`backup/retention.rs` 从容量清单生成只读保留预览：每个来源至少保留一份最新记录，保留数量截止时间的并列记录全部保护；正在使用路径为额外保护，不能代替近期记录。旧格式无来源记录一律保留，清单有任何不可读项则所有条目受保护。返回逐条原因、候选数及正文/清单逻辑容量估算，容量溢出返回错误。预览不执行删除、不验证正文，也不是执行清理的授权；后续执行必须取得与备份/恢复协调的锁、重新扫描并验证候选及保留副本内容，拒绝过期结果。备份设置页已接入只读预览，默认每来源保留 3 份，可切换 1/3/5/10 份；数量变化触发后台重扫并按请求号拒绝旧结果。显示候选数量、容量估算及逐条原因，当前窗口备份/恢复任务期间暂停展示。该选择仅用于当前预览，不保存为自动清理设置。同机同用户跨进程任务锁已接入创建、完整校验及恢复；后端清理执行沿用该锁，界面尚未开放。


`backup/locking.rs` 以规范化备份父目录的摘要命名锁文件，放在当前用户临时目录的专用锁目录内。Unix 校验该目录归当前用户所有且权限为 0700 范围，拒绝链接/特殊锁文件；不在备份介质内写锁，支持只读来源。创建备份持有独占锁，完整校验和恢复全过程持有共享锁，冲突立即返回可重试错误；内部已持锁的校验路径避免重复加锁。锁文件不主动删除，以免破坏并行进程持有的锁身份。该协议只协调共享此用户运行目录的本机应用进程，不协调其他机器、其他用户或绕过协议的文件操作；共享存储上的跨机器清理仍需额外保护，当前尚无删除执行入口。

`backup/cleanup.rs::prepare` 在独占目录锁内重新列出备份并重算保留预览，要求与用户看过的记录、候选容量和保护状态完全一致；有异常项或无候选时拒绝继续。对候选和保留副本均执行完整内容校验，防止同长度损坏的新备份成为删除旧的完好备份的依据；候选根目录含清单/正文目录之外的文件时拒绝。校验后再次比较元数据清单，返回的 `Checked` 在其生命周期内持锁，但不是可持久化的删除授权，外部文件变化仍需执行时复核。后端已增加执行 API，界面执行入口尚未开放。


`Checked::execute` 消费持锁预检结果，首先重新校验完整清单、目录身份及正文并与预检快照比较。候选不覆盖地移动到同父目录独立 `.inkstone-backup-cleanup-*` 隔离目录，保持位置无关的目录身份校验，再次核对完整清单/正文和额外文件后移除。隔离校验失败尝试不覆盖回滚，原位置被占用时保留隔离内容并报告路径；删除失败报告已完成数量和剩余隔离目录。统计为已删除记录的逻辑字节数，非文件系统实际释放量。仅支持本机受同一锁协议约束的写入者，不承诺跨机器或任意外部持续改写的安全性。强退可能留下完整或部分隔离目录，其枚举和处理仍待补齐；在这些边界及确认流程完成前，UI 仍只有预览。
