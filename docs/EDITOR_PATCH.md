# GPUI Base 换行补丁

## 展示投影复验（2026-10-01）

原生续验追加了 IME 稳定布局补丁：预编辑事务在 `push_history` 中重定位未编辑的 DisplayObject，保留 ID / 尺寸；被编辑对象失效。组词的行隐藏按源字节锚点重定位后恢复，避免文本变化统一清空隐藏行导致跳动。应用通过 `is_composing` 暂缓解析结果与测量高度安装，确认 / 取消后更新。组件新增中文 / emoji 范围回归，应用回归覆盖对象前组词与确认 / 取消；实际微软拼音候选窗复验通过。最新组件全套 1,231 项通过。

无语法高亮器时，应用文字装饰仍需要按可见行裁剪后再生成字节长度 run；否则折叠或跨行展示对象隐藏的源码会使后续样式偏移。`input/base/element.rs` 为该路径补齐范围裁剪，并在投影片段交给平台字体系统前复用 `align_runs_to_char_boundaries`。真实 Windows release 重开测试库曾触发 DirectWrite 的 UTF-8 切片异常，修复后原生重开通过。

新增组件回归验证 CRLF、隐藏中文行、emoji 和后续装饰的字节范围。补齐组件测试夹具新增字段，将脚注选区回归移动到可访问对象状态的 `text/node.rs`，验证前置文字、上标对象、后置文字和跨对象选区。独立副本中执行组件全部 1,230 项测试通过；副本位于忽略的 `target/component-audit/`，不更改发布依赖锁。

## 原因与选择

原生 Windows release 的 360,022 字节超长单段测试中，`👩‍💻` 在软换行边界被拆成两行。进一步实测发现 `Shift+Left` 可能只选中 `é` 的组合附加符号。GPUI 的宽度估计与 Base 的光标边界使用 Unicode 标量，显示行和交互端点需要限定到完整字素。

公开接口允许开启 / 关闭软换行，但没有替换换行与光标边界策略的钩子。关闭软换行不满足需求，独立重写编辑器成本过高。因此维护一个范围受控的 Base 补丁。主 GPUI 仍统一为 gpui-pre 0.3.7，未引入第二套类型或 Zed editor。

## 来源与许可

- vendored crate：gpui-base 0.7.0，原始 crates.io 发布包。
- 上游提交：`0c830f4d257e69fdd17200650533ab4ca9a40cc0`，目录 `crates/base`。
- Apache-2.0；随源码保留 `vendor/gpui-base/LICENSE-APACHE`。
- Cargo `[patch.crates-io]` 让 Component、Kit 与应用统一使用这一份 Base。

## 改动范围

1. `src/input/editor/display_map/grapheme_wrap.rs`：把估算换行点向前收敛到字素起点，去重并排除空显示行。单个字素宽于行宽时允许该字素超宽，不拆分字素。
2. `text_wrapper.rs`：在原换行算法输出进入 WrapMap 前应用上述边界规则。
3. `display_map/mod.rs`：注册内部模块。
4. `src/input/base/grapheme_cursor.rs`：通过 Rope 块和 GraphemeCursor 寻找完整字素端点，正常路径不展平整篇文本。
5. `base/state.rs`：在可见光标 / 选区边界规范化处调用该策略；新增 `reveal_cursor`，复用组件滚动逻辑，在视口重排后显示当前光标，保留选区方向与撤销历史。
6. `input/mod.rs`：注册光标边界模块。

文档文本、撤销算法、精确 UTF-8 / UTF-16 源码接口和保存逻辑不变。修改的是显示行分界和可见光标 / 选区端点。

原锁定的 unicode-segmentation 1.12.0 在跨 Rope 块 ZWJ 测试中也返回了错误边界。1.13.3 发布源码包含相应 chunk-boundary 修复测试，依赖已统一锁到 1.13.3；同一回归在升级后通过。参见[上游源码](https://docs.rs/crate/unicode-segmentation/1.13.3/source/src/grapheme.rs)。

## 维护与验证

- `cargo test --test grapheme_wrap` 编译实际补丁文件，覆盖 ZWJ emoji、组合附加符号、旗帜和超宽单个字素。
- `cargo test --test grapheme_cursor` 跨多个 Rope 块，对每个标量位置比较完整字符串字素边界；覆盖 ZWJ、旗帜序列与长组合字符序列。
- GPUI 键盘事件测试实际执行 Shift+Left、删除和撤销，确认不会拆开 emoji / 组合字符。
- `cargo test --locked` 同时运行应用和接口回归。
- 必须复测原生软换行、鼠标选择、中文候选框和窗口重排；单元测试不能代替。
- 升级 Base 时比较这六个文件，确认新上游是否已处理字素边界；若已修复则移除 patch 和 vendor。
- vendor 包约 4 MB；维护重点是显示行与源码偏移一致，不能只检查渲染结果。

当前原生回归结果以 TESTING.md 为准。

## 视口重排

实测最大化后还原窗口会保留选区，却把选区留在可见区域之外。组件公开的定位方法会改变选区，因此新增上述窄接口。应用观察编辑区域尺寸，只在原光标可见且编辑器有焦点时，于下一帧调用它；用户主动滚离光标时不会强制滚回。可见性判断把未滚动的光标几何加上滚动偏移，再与输入区域相交。

自动回归覆盖变宽再变窄、反链栏出现导致编辑区变矮，验证源文、选区方向、光标可见性。最终版本已原生复查：360,022 字节单段的文末选区在最大化、还原后仍可见，源码范围与文件哈希不变。升级 Base 时还需核对布局通知时机和 `scroll_to` 行为。


## Obsidian 工作区新增补丁

`vendor/gpui-base/src/tree.rs` 的 TreeItem 新增显式 `folder(bool)` 标记，使没有子文件的空目录也能正确显示为目录。目录仍使用组件原有的展开、选择和虚拟列表逻辑；普通叶子行为不变。工作区会话测试覆盖空文件夹显示与恢复。


## 分屏共享撤销

`input/base/state.rs` 将已有的 `undo` / `redo` 方法公开，方法实现不变。镜像编辑视图通过动作捕获调用正文所有者的撤销栈；不会为同一文件启动第二个保存者。新增工作区测试覆盖双向同步、共享撤销/重做、独立焦点、预编辑与外部冲突。


## 阅读任务和源位置定位

- `text/text_view.rs`、`text/state.rs`、`text/node.rs` 增加可选任务框回调，传递 Markdown 列表项的来源偏移；组件本身不修改文档。应用通过来源映射更新真实笔记，保留基线检查与历史。
- `text/range_highlight.rs`、`text/stream_fade.rs` 增加源偏移到渲染块位置的查询，识别嵌套列表项和引用中的段落；阅读锚点不再强制切回源码。
- 应用侧 `src/rendering.rs` 保存链接、嵌入段落与任务的来源；旧预览仅在原文快照仍匹配时允许写入。


## 实时预览显示映射

- `input/editor/concealment.rs` 管理不进入文档历史的零宽源跨度；输入引擎平移未受影响范围，并拒绝拆分 Unicode 字素。
- 整行隐藏使用独立的逻辑行集合，与用户折叠区间合并投影但不加入折叠记录；只接受首行之后的有效行首锚点，正文编辑会清除。该行所有软换行一起隐藏，布局改变时重新计算隐藏区间，保持源偏移和行高映射一致。
- 编辑状态提供全部选区范围，宿主据此展开任一光标正在编辑的语法；Setext 下划线行与行内标记共用搜索和选区显示规则。
- `set_concealed_ranges_with_widths` 可为隐藏源范围预留控件宽度，复用软换行和源坐标映射；拒绝无效宽度与重叠替换。实时任务复选框使用此接口在可见源位置绘制控件，正文仍保留原始任务标记。
- 源坐标查询拒绝位于当前可见行之前的偏移，不再将折叠行或视口上方的源范围饱和减到下一条可见行的列零；这些范围按 API 约定返回无坐标，避免悬浮控件落在错误行上。
- `input/editor/line_typography.rs` 为逻辑行提供字号和行高比例，锚定在源前缀。`display_map` 维护稀疏的高度修正区间，不需要为每个软换行分配高度表。
- `text_wrapper` 在包装和绘制时使用相同字号；`InputLine` 的片段始终使用源字节偏移。隐藏前缀不会产生零内容软换行。
- 光标、命中、选择、输入法位置、页移动和滚动共享行高投影。重排时仅跟随先前可见的焦点光标，保留主动滚离光标的行为。

## Markdown 结构编辑

- `input/base/state.rs` 增加 `apply_source_edit`，接收 UTF-8 替换范围与编辑后选区，包成一个原子事务并保存真实原选区。拒绝组合输入期间和多个光标的宿主替换。
- `src/markdown_edit.rs` 只计算列表/引用的源编辑；`EditorPane` 捕获相关按键，跳过补全菜单、阅读模式与输入法组合状态。未匹配的按键继续交给原编辑器。

## Markdown 折叠

- `src/index.rs` 从语法树生成折叠范围。编辑器异步解析完成后安装候选范围，工作区命令和左侧按钮共用折叠操作。
- `fold_map` 更新候选时同步已折叠区域的终点并使投影失效；全部折叠一次重建。编辑控件折叠后把隐藏光标移回区域首行，显式选区和搜索目标会展开覆盖它的区域。
- 折叠按钮跟随可变行高；`ViewState.folded_lines` 保存每个视图的独立折叠状态，旧配置默认展开。

## 多光标配对退格

- `InputBaseState::pair_deletion_at` 复用单光标的配对、转义与语法判断。
- 只有全部光标都位于空配对内部时批量删除左右符号；否则统一使用普通退格，包括非空选区。
- 使用现有批量删除事务记录原选区，撤销与重做保留光标身份及位置。

## 批量包围选区

- `surround_selections` 统一单个及多个非空选区的配对输入，批量应用一次事务，再恢复选区身份、顺序与方向。
- 选区偏移按文档顺序累计计算，原活动选区不因排序变化；新增闭合符号跟随撤销历史记录。
- 跨行的普通括号/强调选区替换为符号对；反引号保留跨行正文。混合空选区和三反引号前缀仍需扩展。

## 多光标括号与跳过

- 批量配对规划允许空光标插入非对称括号，在应用前检查所有位置；单光标的显式范围输入仍保留原有范围限制。
- 闭合符号检测接收各光标位置；只有全部光标符合条件时才同时移动，并消费已生成闭合符号记录。
- 跳过只改变光标，不写撤销历史；新增回归覆盖配对、跳过、继续输入、撤销和重做。

## 多光标对称配对

- 批量配对可同时规划插入、选区包围及闭合符号跳过，全部位置验证成功后才修改文本或消费记录。
- 跳过与插入混合时，在事务开始处记录原配对状态，撤销后可再次跳过；没有文本改动时不产生历史项。
- `auto_close_padding` 共用围栏换行及引用/列表前缀规则，避免多光标路径与单光标路径分离。

## 选区补齐围栏

- 已有双反引号前缀的非空选区，复用围栏前缀规则为正文按需添加首尾换行；已有 LF/CRLF 边界不会重复添加。
- 新选区仅覆盖原正文，新增换行留在选区之外；闭合符号记录定位于换行之后，多个选区累计映射各自偏移。

## 逐个选择相同文本

- `SelectNextOccurrence` 动作绑定 Ctrl+D / Cmd+D，并注册在多行输入控件中；组词期间不改变选区。
- 空选区按字素扩展到 Unicode 字母/数字/下划线词；相同非空选区从最后一个选区末尾继续搜索并回绕，整词与显式子串采用对应规则。
- 保留选区身份与活动光标，跳过重叠及字素内匹配；选区变化打断输入撤销合并，不改变文档内容。

## 选择全部相同文本

- `SelectAllOccurrences` 从一个非空选区选择全部字面匹配，保留活动匹配；空光标、已有多选区、组词中或超过参考上限时不改变选区。
- `Selections::merge_overlapping` 保留相邻非空范围，继续合并实际重叠与边界重复光标，匹配参考的选择规范化规则。
- 主应用以 Ctrl+Shift+L 和命令面板调用，并通过已有快捷键配置处理用户自定义侧栏绑定的冲突。

## 行移动与转换后选区

- 应用层 `line_edit::move_lines` 规划行块重排与选区偏移，主应用命令通过现有 `apply_selection_transform` 批量应用。
- 非空转换结果选区保留原方向，折叠为光标时清除反向标记。
- 相同文本但选区位置不同的转换仅更新选区、打断输入合并并滚动，不修改之前的撤销记录。

## Unicode 相同文本匹配

- `base/occurrences.rs` 按参考搜索游标逐字符进行兼容分解，并将规范化结果的偏移映射回原文；不会规范化或改写笔记本身。
- 依赖固定为 `unicode-normalization 0.1.25`，使用其 [NFKD 接口](https://docs.rs/unicode-normalization/0.1.25/unicode_normalization/trait.UnicodeNormalization.html#tymethod.nfkd)，根锁文件只新增此包。
- 搜索可从原文的指定位置开始，兼容字符的重叠映射去重；调用方继续检查字素边界和整词规则。

## 链接点击修饰键

- LSP 文档打开增加可选 `show_document_with_modifiers` 主机回调；鼠标定义跳转传入原事件修饰键，键盘跳转传入 None。
- 新回调优先，未处理时仍调用已有 `show_document`，保持原有主机扩展路径。
- 应用按实时预览/源码模式解释新标签意图，阅读链接使用 ClickEvent 的修饰键，工作区统一执行目标打开和标题跳转。

## 删除逻辑行

- `InputBaseState::delete_lines` 按选区计算逻辑行块，正确删除相邻换行符并保留 CRLF，不对预编辑或只读内容执行删除。
- 通过已有显示行定位保留横向位置，再映射到删除后的文档；事务记录完整多选区，撤销恢复原视图选择。

## 选中逻辑行

- `select_lines` 与 `delete_lines` 共用选中行块计算，保留分离块并合并相邻块，完整包含实际 LF/CRLF。
- 选择改变打断文本输入的撤销合并，不修改正文；应用通过命令与平台快捷键调用。

## 命令触发补全

- `input/editor/lsp/completions.rs` 增加显式 `request_completions`，使用 LSP Invoked 触发类型，不伪造键入字符，并清除旧触发位置。
- 菜单已处理的动作停止传播。回归发现 Enter 原先可能继续进入编辑器默认输入，造成换行和残余括号；方向键也按相同消费规则处理。

## Callout 与引用式链接

- Markdown 解析识别 Callout 头行，在保持字节位置的解析副本中拆分标题与正文；原始 Markdown 继续用于复制和源范围映射。
- `Blockquote` 增加 Callout 元数据。标题作为普通段落子节点复用链接/选择处理，正文复用列表、任务、图片等现有渲染。
- 折叠状态由 `TextViewState` 保存，切换阅读模式不会丢失。折叠变化重新测量高度；源位置跳转可展开覆盖目标的提示块。
- 提交解析结果时按实际块重建引用定义，修复原来定义没有进入渲染上下文的问题，也避免继续解析尾部时留下旧 URL。

## 命名脚注

- Markdown 解析先收集定义和可达引用，再把使用的定义排列到文末；编号、定义位置和每次引用的位置保存在解析上下文。
- 引用通过带基线的原生行内元素显示上标，私有跳转链接由 TextView 内部处理，不交给系统浏览器。
- 显示索引记录行内源范围，返回脚注引用时定位到具体字符；重叠源范围优先选择更小的块，支持移到文末的嵌入脚注。
- 含脚注的追加重新解析完整文档并使高度缓存失效，避免移动脚注后重复正文或沿用错误高度。
- 应用的阅读转换为不同源文件分配独立标识，并补入章节嵌入依赖的脚注定义；这些改变仅用于阅读呈现。
# 补全菜单展示补丁

## Markdown 展示对象投影

- `DisplayObject` / `DisplayProjection` 为临时展示元数据，安装时检查完整源快照、字素边界、尺寸、基线和重叠范围。它们与持久化 `InlineToken` 分离，编辑或正文重置时清除。
- 复用既有宽度替换、整行隐藏和像素高度映射：首行预留原生对象宽度，其余源行隐藏；行高度支持最高 512 倍，以承载表格、图片和公式。
- 主机将投影与文字标记层合并，按选区决定是否展开源码。定位接口复用软换行、滚动及折叠后的源范围几何。
- 根项目 `tests/display_objects.rs` 验证 CRLF 跨行投影、240px 高度、源码复制、编辑清除、撤销与过期快照拒绝；组件严格 Clippy 通过。
- `DisplayScrollAnchor` 保存可见源位置和文档版本，异步高度变化后恢复其视口像素位置；版本变化时拒绝旧锚点。
- HTML 上下标使用继承字体和基线的原生行内对象，内部链接/图片复用父视图回调；details 复用原生折叠状态，并分配稳定源位置。
- 片段视图可以覆盖脚注编号；文末视图在普通块插件前过滤重复正文，原始解析仍负责引用顺序、脚注导航和完整来源映射。
