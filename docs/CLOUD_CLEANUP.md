# 云端旧对象清理：协议边界

本记录对应待办第 7 项。当前设置页已接入只读预览、升级说明、确认执行、停止及部分结果反馈；底层包含维护锁、代次隔离、持锁核验和删除执行 API。macOS 原生基本流程已验证，真实服务商与完整原生矩阵尚未完成。以下区分已实现步骤与完整协议仍待验证的约束。

## 当前协议不能直接删除未引用对象

`sync.rs::synchronize_cancellable` 的流程为读取清单、下载、上传、核对本地、条件发布、应用本地变更。`webdav.rs` 用对象 SHA-256 作为路径，以 `If-None-Match: *` 创建；已有对象会重新下载校验。清单发布通过强 ETag 的条件 PUT 排除过期发布。

容量统计在 PROPFIND 前后比较清单和 ETag，但上传对象不会修改清单。以下时序中统计结果完全稳定，删除仍然不安全：

1. A 读取清单 M，上传新内容 X，尚未发布。
2. B 读取 M、列出对象 X、再次读取 M；X 被统计为未引用。
3. B 删除 X。
4. A 用 M 的 ETag 发布引用 X 的新清单；条件 PUT 成功，但正文已丢失。

重复读取清单、只删除旧对象、对象 DELETE 自身的 If-Match、本机独占锁，都不能单独排除此竞争。旧对象也可能被新编辑重新引用；本机锁不能约束另一设备。

## 开放删除前必须具备的保护

- 同步发布与清理必须共享远端可执行的互斥或隔离协议；它须覆盖上传完成到发布完成的窗口，并防止暂停后恢复的旧清理者继续删除。
- 正在使用旧快照的读者必须可以安全完成，或明确失败并重试，失败不得应用部分本地变更或推进基线。不能把取消按钮当作已取消在途 HTTP 请求的证明。
- 当前清单、受保护恢复记录、仍有发布资格的在途上传所需对象不能列入可删除集合；预览只是快照，执行须重新验证授权和保护集合。
- 崩溃及不确定的 HTTP 结果必须可恢复；不得仅按客户端时间或过期租约假设旧请求已停止。第二个清理者与旧清理者的交错也必须验证。
- 旧客户端不能忽略新规则后继续写入。现有 version 1 解析会忽略额外 JSON 字段，因此添加 `cleaning` 字段不能形成保护。需要明确的协议升级边界及旧版本拒绝行为。
- 若以临时不支持版本阻止客户端，结束时直接恢复原清单字节也不充分：服务端可能再次给出原 ETag，使持有旧 ETag 的请求重新有效。必须防止这种 ABA 情况；更不能在存在未决删除请求时恢复写入。
- 服务端不具备所选协议需要的原子条件操作时，保持容量统计可用，并明确不支持清理。真实服务商验收与内存/HTTP 模拟测试分别记录。

底层互斥采用服务端递归独占写锁，已增加显式推进 version 2 清单维护代次的 API；只读预览、持锁核验和删除执行 API 已实现，界面已接入，完整服务商并发/崩溃验收仍未完成。锁与代次隔离都不能单独作为删除授权。

## 分步验证入口

现有 `webdav::capacity::tests::capacity_http_is_read_only_and_rejects_manifest_changes` 验证统计只读和清单变化拒绝。新增 `sync::tests::unsupported_remote_version_preserves_local_edits_and_baseline` 验证完整同步入口遇到未知版本时不会开始正文传输或发布，且保留本地编辑和已保存基线；这仅证明未来升级的一个前置条件。

后续协议测试至少覆盖：上传后发布前清理、旧快照读者、同内容再次引用、预览后远端变化、双清理者、每个远端变更前后强退、响应丢失后重试、过期请求恢复、旧客户端在途发布及 ETag ABA。界面已接入预览、确认与停止，后续仍须完成原生及真实服务商验证。清理仍是未完成项。

## 已实现：维护锁生命周期

依据 [RFC 4918 的 LOCK 规则](https://www.rfc-editor.org/rfc/rfc4918.html#section-9.10) 与 [If 条件求值规则](https://www.rfc-editor.org/rfc/rfc4918.html#section-10.4)，新增 `WebDav::lock_maintenance` 及 `MaintenanceLock`，仅供后台工作线程使用：

- 请求 `inkstone/` 的递归独占写锁，携带 `If-Match: *`，不主动创建同步目录；只接受 HTTP 200。
- 有界读取响应，验证唯一令牌、锁根、独占写类型、完整深度及 1–300 秒期限。令牌可用但正文不合规时尝试释放；缺失或歧义令牌无法安全用于释放，需由服务端处置。
- 续期通过锁根的正向 `If` 条件，不含允许任意成功的备选条件。失败或不确定响应使句柄永久失效；调用方须重新申请并重新验证计划。
- 显式释放返回结果；遗漏释放时 Drop 最多用 5 秒尝试一次。失败不宣称已解锁，最终过期由服务端决定。期限仅用于续期调度，不作为后续变更授权；后续每个写请求仍必须原子检查锁条件。

本轮 HTTP 模拟测试验证协议序列、校验与失败行为，没有证明具体服务商正确执行锁，也没有加入 DELETE、清单升级或界面入口。永久清单隔离的 API 已在下一节实现；接下来建立持锁预览和执行，不能直接把已有容量统计中的未引用对象传给删除接口。

## 已实现：显式版本升级与维护代次

`MaintenanceLock::advance_manifest` 是会修改云端清单的后台 API，由确认清理后的后台工作调用。普通同步不会自动调用它。确认界面说明所有设备需要支持新格式。

1. 持锁读取当前清单和强 ETag，将格式设为 version 2，维护代次从 1 开始或递增；文件映射原样保留。未知清单字段及代次溢出拒绝处理。
2. 同一个 PUT 同时提交锁根 `If` 条件和清单 `If-Match`（首次创建用 `If-None-Match: *`）。锁失效或清单已变都不能继续。
3. 读回必须与待提交清单完整一致，且 ETag 必须不同于先前值。失败使句柄失效；不确定结果也不得回滚到旧字节，应重新持锁检查。
4. 普通同步接受旧版和有效 version 2，发布时保留格式与代次，不降级。已记录新代次的本地基线遇到远端格式或代次回退时停止。旧版基线及成功时间仍可读取。

永久保留 version 2 使旧客户端重新读取时拒绝同步；持有旧修订的在途发布通过条件 PUT 被拒绝。后续每轮清理递增代次，即使文件映射相同也不恢复清理前的表示；由此避免在正常协议操作中回到清理前的 ETag。禁止依赖临时格式标记后还原 version 1。协议之外的手工远端回滚或不遵守条件操作的服务端不在此保证内。

在途上传如果已被新代次取消发布资格，其本地正文仍由该客户端保留，后续应重新同步上传。保护集合和候选列表的实现必须在代次切换后重新计算。删除执行还须遵守下一节的逐请求锁条件及结果核验；不能仅据此宣称完整清理已经安全可用。

## 已实现：对象预览与持锁正文核验

`WebDav::preview_cloud_cleanup` 只读取清单和对象列表，并再次读取清单验证一致性；结果包含候选/保留对象的去重数量和字节数，内部绑定规范化远端身份、清单修订和完整对象长度映射。缺失引用、未知记录、异常类型或超出单对象限制会拒绝生成清理预览。原容量统计复用列表解析，仍以统计用途显示未知记录。

`prepare_cloud_cleanup` 在后台取得维护锁后重新生成预览，要求与用户确认的快照完全一致。随后逐个续期并流式核验所有对象的长度和 SHA-256，包括保留对象；不将全部正文放入内存。全部通过后才推进维护代次，再核对新清单和对象列表并确认锁仍有效，返回持锁的 `CheckedCloudCleanup`。显式释放可报告失败，放弃句柄会尝试释放。

预览本身不升级格式；prepare 会升级/推进代次，已由确认界面明确说明。核验前取消不修改清单，核验中取消停止后续请求；推进代次后的取消不还原旧清单。Checked 不是跨重启或锁失效后可复用的删除授权。新增 execute 会重验锁与清单，逐个提交带锁条件的删除并记录中断结果，见下一节。

## 已实现：逐对象删除与部分结果

`CheckedCloudCleanup::execute` 消费已核验句柄，先续期并重读精确快照，然后仅遍历清单未引用对象。每次 DELETE 前续期、检查取消，并把锁根的正向条件交给服务端；不自动重获锁或重试不确定请求。仅接受 HTTP 204，随后以同一锁条件 HEAD 检查 404，才将该对象及已核验字节数计入完成报告。最终重新核对剩余对象和清单，再显式释放锁。

取消停止后续对象，已开始的单个删除会完成结果核对。`CloudCleanupFailure` 分开记录已确认完成前缀、一个可能已完成但未确认的请求、取消状态及释放失败。412/423 按条件拒绝处理；连接断开、异步接受、非预期状态或未能确认缺失都不会计入成功，也不继续删除。释放失败不能抹掉已完成数量；所有结果都不还原维护代次。

当前测试使用实际 HTTP 传输和确定性脚本响应，验证请求目标/条件、控制流及错误归类；尚未证明真实服务端的并发互斥、条件求值与变更原子性，也未覆盖全部强退时序。服务端必须同步完成受条件保护的单对象操作，不支持异步删除语义。有状态多客户端交错已补充如下；界面已接入预览、升级说明、确认、停止及完成/部分完成反馈，真实服务商与进程强退验收仍待完成。

## 已验证：有状态服务模型中的客户端交错

新增测试服务实际保存对象正文和清单字节，以清单内容 SHA-256 生成 ETag，在同一服务端互斥区内评估条件并执行写入，维护独立锁令牌。真实 WebDAV 客户端通过 HTTP 操作该模型；暂停同步线程的通道有超时，不依赖任意 sleep 决定交错顺序。

- 同步线程已上传、尚未发布时，另一客户端持锁清理；期间第二把锁和无令牌写入被拒绝，当前引用对象仍可读取。释放后过期发布被拒绝，本地正文和基线保留；重新同步上传成功，另一笔记库最终取得相同正文。
- 旧维护锁被撤销、另一客户端取得新锁后，旧句柄既不能删除，也不能释放新锁；新维护会话可完成清理。
- 续期成功到 DELETE 之间撤销锁，服务端条件检查拒绝删除；重新预览并持新锁可以继续。
- 服务端已删除但响应丢失时，客户端报告不确定、释放锁；新预览只处理剩余候选，不重复计入未确认的删除。
- 读者持有的旧快照对象被后来清理后，下载失败不更新本地正文或基线；再次同步读取当前清单可收敛。

各场景核对当前清单引用对象存在且正文哈希正确。该服务模型假设条件求值与单个变更串行一致，尚不能证明真实服务商遵守同样约束，也不是物理断电或云端进程崩溃实验。

## 已实现：设置页清理闭环

预览绑定笔记库代次和当前表单摘要；修改输入或切库使旧结果失效。确认前必须无冲突的后台文件任务，执行后持有任务票据直到工作完成，取消不提前释放。云端任务不持有阻止本地手动保存的独占票据；同步、配置保存和切库仍协调等待。过期回调仅释放自己的票据，不覆盖新上下文。

GPUI 与实际 HTTP 回归覆盖成功、停止、过期回调、重复执行拒绝，以及清理期间明确手动保存。未保存正文、原 Markdown 和未持久化表单不会被清理偷偷保存；按钮 Tab 导航包含新预览入口。原生视觉、真实服务商和云端清理进程强退仍待验收。

## 已验证：清理客户端强退与新进程继续

有状态服务在创建锁、提交清单代次和删除首个对象后分别扣住响应，父进程强杀真实客户端子进程。没有析构解锁；遗留租约阻止再次加锁，测试服务显式模拟租约过期后，新客户端进程重新预览并完成剩余对象。当前引用、正文哈希、本地未同步修改和基线均保留。该证据不涵盖服务端自身崩溃、物理断电、真实服务商及原生 GUI；不能把测试中的显式租约过期等同于真实服务商期限验收。

macOS release 基本流程已验证预览/确认/取消、成功反馈和未保存内容保护；本机 HTTP 模型核对删除两个候选、保留引用及释放锁。详细范围与截图位置见 [验证指南](TESTING.md)，完整原生中断与服务商验收仍未完成。
