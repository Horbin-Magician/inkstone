# 云端旧对象清理：协议边界

本记录对应待办第 7 项。当前仅有云端容量统计，尚未开放删除；以下是代码审查得出的实施约束，不是已实现或已通过验收的清理协议。

## 当前协议不能直接删除未引用对象

`sync.rs::synchronize_cancellable` 的流程为读取清单、下载、上传、核对本地、条件发布、应用本地变更。`webdav.rs` 用对象 SHA-256 作为路径，以 `If-None-Match: *` 创建；已有对象会重新下载校验。清单发布通过强 ETag 的条件 PUT 排除过期发布。

容量统计在 PROPFIND 前后比较清单和 ETag，但上传对象不会修改清单。以下时序中统计结果完全稳定，删除仍然不安全：

1. A 读取清单 M，上传新内容 X，尚未发布。
2. B 读取 M、列出对象 X、再次读取 M；X 被统计为未引用。
3. B 删除 X。
4. A 用 M 的 ETag 发布引用 X 的新清单；条件 PUT 成功，但正文已丢失。

重复读取清单、只删除旧对象、对象 DELETE 自身的 If-Match、本机独占锁，都不能单独排除此竞争。旧对象也可能被新编辑重新引用；本机锁不能约束另一设备。

## 开放删除前必须具备的保护

- 同步发布与清理必须共享远端可执行的互斥或隔离协议；它须覆盖上传完成到发布完成的窗口，并防止暂停后恢复的旧清理者继续删除。
- 正在使用旧快照的读者必须可以安全完成，或明确失败并重试，失败不得应用部分本地变更或推进基线。不能把取消按钮当作已取消在途 HTTP 请求的证明。
- 当前清单、受保护恢复记录、在途上传所需对象不能列入可删除集合；预览只是快照，执行须重新验证授权和保护集合。
- 崩溃及不确定的 HTTP 结果必须可恢复；不得仅按客户端时间或过期租约假设旧请求已停止。第二个清理者与旧清理者的交错也必须验证。
- 旧客户端不能忽略新规则后继续写入。现有 version 1 解析会忽略额外 JSON 字段，因此添加 `cleaning` 字段不能形成保护。需要明确的协议升级边界及旧版本拒绝行为。
- 若以临时不支持版本阻止客户端，结束时直接恢复原清单字节也不充分：服务端可能再次给出原 ETag，使持有旧 ETag 的请求重新有效。必须防止这种 ABA 情况；更不能在存在未决删除请求时恢复写入。
- 服务端不具备所选协议需要的原子条件操作时，保持容量统计可用，并明确不支持清理。真实服务商验收与内存/HTTP 模拟测试分别记录。

底层互斥采用服务端递归独占写锁；尚未实现清单的永久版本升级、发布隔离和删除流程，仍需证明上述不变量。锁本身不能阻止释放后旧客户端用先前 ETag 发布，因此不能单独作为删除授权。

## 分步验证入口

现有 `webdav::capacity::tests::capacity_http_is_read_only_and_rejects_manifest_changes` 验证统计只读和清单变化拒绝。新增 `sync::tests::unsupported_remote_version_preserves_local_edits_and_baseline` 验证完整同步入口遇到未知版本时不会开始正文传输或发布，且保留本地编辑和已保存基线；这仅证明未来升级的一个前置条件。

后续协议测试至少覆盖：上传后发布前清理、旧快照读者、同内容再次引用、预览后远端变化、双清理者、每个远端变更前后强退、响应丢失后重试、过期请求恢复、旧客户端在途发布及 ETag ABA。协议验证后再接入预览、确认、取消与恢复界面。清理仍是未完成项。

## 已实现：维护锁生命周期

依据 [RFC 4918 的 LOCK 规则](https://www.rfc-editor.org/rfc/rfc4918.html#section-9.10) 与 [If 条件求值规则](https://www.rfc-editor.org/rfc/rfc4918.html#section-10.4)，新增 `WebDav::lock_maintenance` 及 `MaintenanceLock`，仅供后台工作线程使用：

- 请求 `inkstone/` 的递归独占写锁，携带 `If-Match: *`，不主动创建同步目录；只接受 HTTP 200。
- 有界读取响应，验证唯一令牌、锁根、独占写类型、完整深度及 1–300 秒期限。令牌可用但正文不合规时尝试释放；缺失或歧义令牌无法安全用于释放，需由服务端处置。
- 续期通过锁根的正向 `If` 条件，不含允许任意成功的备选条件。失败或不确定响应使句柄永久失效；调用方须重新申请并重新验证计划。
- 显式释放返回结果；遗漏释放时 Drop 最多用 5 秒尝试一次。失败不宣称已解锁，最终过期由服务端决定。期限仅用于续期调度，不作为后续变更授权；后续每个写请求仍必须原子检查锁条件。

本轮 HTTP 模拟测试验证协议序列、校验与失败行为，没有证明具体服务商正确执行锁，也没有加入 DELETE、清单升级或界面入口。接下来先实现永久清单隔离，再建立持锁预览和执行；不能直接把已有容量统计中的未引用对象传给删除接口。
